Maze creator

Click a wall segment to add or remove it (red = wall). The boundary ring is fixed. Click a cell to set the goal (green). Start is (0,0), launch north.

Below the grid the editor derives what the rig list needs: the corridor cells reachable from the start, the loop START → GOAL → START (shortest out, shortest back that avoids the out leg where it can), the turn events with their hands, and any alcove (reachable but off the loop). Turns in adjacent cells are grouped the way the compiler groups them: alternating hands = a diagonal (45-in, 45-out, dashed centre line), a same-hand pair with a staircase step on both sides = a V, with a staircase on one side only = a 135 (one arc from the diagonal into the corridor, or the reverse; the mouse's r135 switch turns it off), any other same-hand pair = a U. Then the compiler's own fit runs on it, pass by pass as the mouse does at the start line: radius ladder, then the speed rung, then un-merging the one feature that will not fit and compiling again. Amber ring = a hairpin or staircase un-merged into its 90s, or a demoted radius; blue = a corner speed-capped (the cap is written under it); red = refused, which should no longer happen on any valid maze.

Saved rigs live in this browser (localStorage) and appear in the Rig dropdown with a “✎”; Download JSON to keep one, Load JSON to bring it back.

Corner types

A TYPE is what the mouse can recognise on a maze it has never seen: kind (90 / U / 45-in / 45-out / V), hand, radius, and the gate class it got (LOCK = its own inside edge, INHERIT = the previous corner's correction, NO_EDGE = blind, DIAG = placed by the diagonal's posts). Exit "wide" is + toward the OUTSIDE of the turn, whichever wall that is. Settled = n ≥ 5, |mean err| ≤ 1°, σ ≤ 1°, |mean wide| ≤ 12 mm. Kept in this browser between sessions; export to carry it.
